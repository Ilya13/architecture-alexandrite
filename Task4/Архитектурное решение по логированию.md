# Логирование

## Анализ системы
Для реализации наблюдаемости системы, нужно реализовать логирование следующих компонентов:
- Shop API
- CRM API
- MES API
- MES
- Messages Queue

**Логи с уровнем INFO:**
- Создание заказа: время, идентификатор покупателя, номер заказа;
- Размещение заказа от продавцов: время, продавец, номер заказа;
- Загрузка 3d модели: длительность загрузки, размер файла, номер заказа;
- Изменение статуса заказа: время, номер заказ, клиент, операторы (если заказ взят в работу);
- Передача сообщений в RabbitMQ: номер заказ, сообщение.

Так же в системе будут использоваться уровни логирования:
- FATAL — при отказе сервиса или оборудования;
- ERROR — ошибочное состояние. Например, «Ошибка обработки 3d модели», «Ошибка http запроса 5XX»;
- WARN — состояние, которое близко к нестандартному поведению системы. Например, «Пользователь неправильно ввёл пароль», «Создано более 100 заказов за 1 секунду», «Изменение статуса не соответствует последовательности».

## Мотивация
Логирование позволяет отслеживать как состояние системы изменяется с течением времени.
Логи помогают при отладке разных компонентов приложения, а также позволяют собирать и анализировать данные о работе системы. Это помогает обнаружить ошибки.

Для данной системы логирование позволит быстрее разрешать инциденты и легче находить ошибки в системе.

Внедрение логирования, повлияет на следующие метрики:
- Среднее время обработки обращения в техподдержку;
- Количество обращений в техподдержку;
- Количество ошибок;
- Среднее время выполнения заказа;
- Количество выполненных заказов.

В первую очередь логирование и трейсинг необходимо настроить для следующих систем: Shop API, CRM API, MES API, так как через эти сервисы создаются и обрабатываются заказы. Безотказность и быстрота работы этих сервисов напрямую влияет на количество заказов, а значит и на прибыль компании.

## Предлагаемое решение
Логирование будет реализовано с помощью `ELK` (ElasticSearch, Logstash и Kibana) — набора инструментов для извлечения, поиска, анализа и визуализации данных. Для агрегации данных из разных источников и передачи их в `Logstach` будет использоваться `Filebeat`.

**Реализация:**
1. Развернуть ELK в системе;
2. Настроить сервисы логирования;
3. Развернуть Filebeat в системе;
4. Настроить Filebeat для сбора логов с сервисов;
5. Добавить в код сервисов API вывод логов;
6. Настроить шаблон индекса для логов;
7. Настроить дашборды в Kibana.

**Безопасность и доступ:**
- Система логирования развернута во внутреннем контуре;
- Доступ реализован через внутреннюю систему авторизации (LDAP);
- Настроено ограничение по ролям (Keycloak).

**Хранение логов:**
- Для каждого сервиса создается свой индекс;
- Логи хранятся в течении 30 дней;
- Когда срок истекает, индекс перемещается на более дешёвый уровень хранения.

**Система анализа логов:**
- Алертинг при высоком количестве ошибок;
- Алертинг при аномальном поведении системы: резкое увеличение количества заказов, высокое количество запросов с невалидной авторизацией.
- Предупреждения о "зависании" заказа.
