# Трейсинг

## Анализ системы
В текущей архитектуре системы заказ клиента может зависнуть или сломаться в следующих местах:

- **Internal Shop &#8594; Shop API** - при загрузке 3d модели в хранилище S3, если файл большой, то запрос может отвалиться по таймауту;
- **CRM API &#8594; Messages Queue** - неверная обработка сообщений брокера, неверный статус заказа в CRM;
- **MES API &#8594; 3d files storage** - долгая загрузка файла;
- **MES API &#8594; Messages Queue** - долгий расчет стоимости заказа;
- **MES &#8594; MES API** - долгая загрузка заказов.ы

Для индикации возможных проблем системы, нужно отслеживать следующие данные:
- trace_id — идентификатор текущей операции;
- span_id — идентификатор подзапроса;
- время поступления запроса в сервис и время, затраченное на его обработку;
- информация об исключениях или ошибках;
- идентификатор заказа;
- статус заказа.

## Мотивация
Трейсинг помогает быстро находить причины, например, медленной работы сервиса. Вместо просмотра всей цепочки вызовов, разработчик может посмотреть, сколько, где и с какими параметрами прошёл вызов. У трейсинга как средства устранения неполадок есть дополнительные преимущества, поскольку любое исключение или ошибка обычно фиксируется вместе со всем контекстом запроса.

Для данной системы трейсинг позволит отслеживать "движения" заказов, быстро реагировать на нештатные ситуации и найти узкие места системы.

Внедрение трейсинга, повлияет на следующие метрики:
- Среднее время с момента создания заказа, до его завершения;
- Процент успешно выполненных заказов;
- Среднее время обработки обращения в техподдержку;
- Number of HTTP 500 - количество ошибок сервисов.

## Предлагаемое решение
Трейсинг будет реализован с помощью платформа наблюдения `OpenTelemetry`, которая предоставляет стандартизированный способ сбора, обработки и экспорта телеметрических данных-сигналов из распределённых систем.

**Технологии и компоненты:**
- OpenTelemetry;
- Jaeger - инструмент и для хранения и визуализации трассировок.

**Реализация:**
1. Развернуть Jaeger в системе;
2. Внедрить SDK OpenTelemetry в Shop API, CRM API, MES API, RabbitMQ;

## Компромиссы
Для принятия решения внедрения трейсинг, необходимо учитывать следующие факторы:
- Ограничения в ресурсах разработчиков;
- Не хватка квалификации DevOps инженеров;
- Ограничения политики компании в выборе стороннего ПО;
- Дополнительные затраты на хранение и обработку логов.

## Безопасность и доступ
- Система сбора трейсинга развернута во внутреннем контуре;
- Доступ реализован через внутреннюю систему авторизации (LDAP);
- Настроено ограничение по ролям (Keycloak).
