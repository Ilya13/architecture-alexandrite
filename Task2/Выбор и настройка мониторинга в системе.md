# Мониторинг

## Анализ системы
Сайт «Александрит» подключён к Яндекс Метрике, это позволяет отслеживать действия клиентов, но не позволяет отследить действия Операторов, пользователей API.
Все сервисы системы перенесены в облако, каждый из инстансов крутится как EC2, базы данных — это Managed services на Yandex Cloud. Это позволяет отследить некоторые показатели состояния виртуальных машин, но этого не достаточно для полной наблюдаемости системы.

## Мотивация
Внедрение мониторинга позволит отслеживать показатели системного уровня, показатели производительности и бизнес-метрики. Это позволит оптимизировать ресурсы системы и выявить высоконапряженные сервисы. Так же мониторинг позволит настроить систему оповещения, для своевременного реагирования на критические ситуации.

Мониторинг бизнес-метрик позволит дополнить аналитику Яндекс Метрики и даст возможность видеть полную картину использования системы клиентами и операторами.

## Выбор подхода
Метод RED подойдет для частей системы с которыми взаимодействуют клиенты и операторы: Internet Shop и MES API, так как для них важны критические показатели системы: скорость и минимум ошибок.

Метод USE подойдет для мониторинга состояния инфраструктуры и позволит выявить узкие места системы и оптимизировать ресурсы.

## Метрики
**Shop, MES, CRM**
- RPS (Number of requests) - даёт представление о пропускной способности сервиса. Эта метрика может помочь избежать сбоев — вы будете отслеживать пиковый трафик и сможете прогнозировать, сколько нужно ресурсов;
- Number of HTTP 500 - это количество неудачных запросов в секунду. Ошибки напрямую влияют на взаимодействие с потребителями;
- Response time (latency) - количество времени, которое уходит на выполнение одного запроса. В совокупности с распределенной трассировкой, эта метрика позволяет отслеживать запрос пользователя в разных сервисах и измерять время, которое заняли события в каждом сервисе.

### RabbitMQ
- Number of messages in flight - даёт представление о пропускной способности очереди;
- Number of dead-letter-exchange letters - позволяет определить количество неверно обработанных сообщений.

### Инфраструктура
- CPU % - для отслеживания утилизации ресурса;
- Memory Utilisation - это среднее время, которое ресурс занят работой;
- Size of S3 storage - для своевременного отслеживания заканчивающихся ресурсов;

## План действий
1. Развернуть и настроить Prometheus;
2. Настроить метрики;
3. Развернуть и настроить Grafana для визуализации метрик;
4. Создать дашборды;
5. Настроить систему оповещения.
